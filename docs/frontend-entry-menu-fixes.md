# Account entry, hero readability and menu expansion

This frontend change makes the existing account menu the single signed-out entry experience. It changes no database migration, subscription, provider configuration or production data.

## Routing and cleanup details

`resolveEntryRoute` centralizes entry behavior. It preserves authenticated routes and defers to the existing loading, recovery and callback states. Anonymous roots (empty hash, `#`, `#/`, root hash queries, `/index.html` and an existing subpath entry) display the account menu before the replacement effect. `history.replaceState` preserves the current pathname, search and history state, and dispatches the existing `hashchange` notification. It creates no redundant history entry; the destination is not itself a root, preventing a loop.

Public legal/invitation/menu links retain their routes. Protected deep links retain their complete URL and display the same account menu until authentication; the existing Auth return flow and subsequent authenticated route parsing can resume them. Callback/recovery paths and Auth query parameters are not rewritten. No Auth service, token exchange, recovery controller or session implementation changed.

Exactly three anonymous `AuthPanel` fallback branches were removed from `App.tsx`: welcome onboarding, onboarding household creation, and the household-setup fallback. No standalone component file or legacy stylesheet was deleted: the surrounding onboarding/access styles and screens still serve authenticated household setup, callback errors and password recovery. The shared `AuthPanel` remains the account/recovery form. Authenticated setup is preserved; menu routes bypass onboarding precedence.

Account uses an `h2` and has no collapse button, summary or false `aria-expanded`. Its form remains mounted and visible while another section opens. The existing hero account action programmatically focuses the heading, without changing the information accordion. The signed-in Account section similarly uses a static heading. Other public buttons retain their panel/expanded ARIA relationships; signed-in details retain native summary keyboard semantics, with their open state controlled by the same small accordion hook.
